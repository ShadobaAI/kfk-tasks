# SPEC-0013: переработка генератора AsyncAPI YAML → XSD

- Статус: `implemented`.
- Дата: 2026-09-15.
- Основание: глобальное ревью `asyncapi2xsd.py`; обратная совместимость не требуется.
- Цель: поддерживаемая генерация произвольной модели XDTO без молчаливой потери требований.

## Область изменения после утверждения

### Поправка: встроенные типы простых полей — утверждена пользователем

Уточнение пользователя: ограничения локальных полей также не требуют отдельного именованного simpleType. По образцу XSDschemeEntepriseData1_25.xsd они сохраняются во вложенном анонимном simpleType элемента. Для локальных enum действует та же форма; общие схемы и UUID остаются именованными. Это уточнение заменяет первоначальное сохранение именованных типов всех ограниченных локальных полей.

Результат поправки: модель различает объявляемые простые типы и локальные типы значений; для полей без фасетов используется встроенный тип, для локальных фасетов — анонимный simpleType внутри элемента. У элемента с анонимным типом отсутствует атрибут type. Ограничения применяются одинаково при выпуске XSD и в скалярных проверках default/examples, без удаления типов из готового XML. Аннотация email для простого элемента массива сохранена на описании поля/коллекции. Три XSD перегенерированы с прежними namespace/prefix/suffix, исходные YAML не изменялись. Проверки: 62 теста прошли, один внешний тест с AsyncAPI-4.15.1.yaml пропущен из-за отсутствия файла; compileall и diff --check прошли. Проверка XDTO/JSON на платформе 1С не выполнялась.

Простые поля и элементы списков без фасетов используют встроенный тип XSD напрямую; отдельный simpleType не создаётся. Общие простые схемы из components.schemas сохраняют именованный тип, UUID и типы с ограничениями сохраняются. Изменение реализуется в одном файле генератора с типизированным различением встроенных и объявляемых типов, без обработки отдельных имён примеров или текстового удаления сгенерированных объявлений. Пользователь поручил затем перегенерировать три XSD-примера. Область поправки: kafka-tools/xdto/generator и examples, пояснение отображения простых типов в документации генерации kafka-adapter, эта спецификация.

### Поправка: пустые массивы — утверждена пользователем 2026-09-15

Пользователь поручил зафиксировать следующую таблицу в генераторе и документации. Для массивов отсутствие minItems означает 0. Nullable вычисляется из отсутствия поля в required; при положительном minItems nullable отключается с предупреждением. Пустой источник для поля вне required при minItems=0 представляется null, для поля в required при minItems=0 — []; при положительном минимуме пустой источник является ошибкой. Заполненные массивы проверяются по minItems/maxItems и ограничениям элементов. Автоматический пропуск полей массива не входит в этот контракт; предложенное x-omit-empty не реализуется. Для остальных типов прежний минимум по умолчанию 1 сохраняется.

Область: kafka-tools/xdto/generator, генерируемые XSD-примеры, kafka-adapter/docs/project и эта спецификация. Изменения сериализатора 1С исключены: выпуск JSON требует отдельной реализации и проверки в назначенном EDT. XSD простого повторяющегося свойства сама по себе не выражает различие null коллекции и null элемента; проверка Python не является доказательством поддержки конечного JSON в 1С.

Результат: общий минимум массивов изменён на 0, nullable отключается при положительном минимуме с SchemaWarning и путём YAML, одиночные контейнеры массивов сохраняют minOccurs=1. Проверка default/examples учитывает новый контракт для прямых массивов и локальных ссылок. Перегенерированы три XSD-примера с прежними namespace/prefix/suffix; YAML не изменялись. Обновлены требования к YAML, описание генерации, README генератора и ссылка на целевой контракт в требованиях адаптера. Выполнены 63 теста, включая матрицу простых/объектных массивов, required/minItems, прямых схем/$ref, null/[]/заполненных массивов и рабочий AsyncAPI-4.15.1.yaml. ### Дополнительные выводы по коду

Проверка входа, разрешение ссылок, регистрация имён и создание XML смешаны. Набор created предотвращает повторную генерацию и одновременно скрывает конфликт разных определений. Типизированной модели между YAML и XML нет.

Обход ссылок проходит произвольные вложенные данные, включая examples и аннотации; ссылка в примере может ошибочно стать зависимостью схемы. Циклы алиасов и невозможные обязательные циклы не диагностируются семантически.

## Проект поддерживаемого решения

### Ответственности

Генератор остаётся одним файлом `asyncapi2xsd.py` по явному уточнению пользователя. Внутри файла разделены четыре ответственности:

1. Загрузка YAML: UTF-8, запрет дублей и рекурсивных структур, проверка корневых словарей, ошибки с местом в источнике.
2. Типизированная модель: определения типов и свойств; отдельно тип, присутствие, повторяемость, фасеты и путь YAML.
3. Компиляция: разрешение локальных ссылок, алиасов, имён, коллизий и представимости в профиле адаптера.
4. XSD и запись: создание XML из проверенной модели, компиляция XMLSchema, атомарная замена результата.

XML не хранит состояние семантического анализа. Реестр различает повторное использование одного типа и конфликт разных типов. Универсальный framework и fluent-билдер XML не нужны.

### Вход и типизация

Обязателен только components.schemas. Каналы необязательны; именование учитывает все разрешаемые сообщения и отклоняет конфликтующие адреса. Общие типы создаются независимо от наличия каналов.

Поддерживаются явные объекты, простые значения, даты, UUID, типизированные enum и локальные ссылки. Примитивный $ref остаётся типом значения. Алиасы разрешаются до целевого определения; цикл алиасов отклоняется. Обязательные рекурсивные модели без конечного экземпляра диагностируются.

Структурные ключи проверяются по явному профилю. Аннотации и x-* не участвуют в обходе ссылок. Неверные значения, required, enum, границы и коллизии выявляются до генерации XML.

Null, логическая композиция, внешние ссылки и произвольные словари не включаются в первоначальный профиль без отдельного точного преобразования. Они отклоняются, а не имитируются более слабой схемой.

### Представимость

Генератор моделирует объявленные properties. Отсутствие additionalProperties не объявляется равнозначным additionalProperties=false. Полная эквивалентность произвольной JSON Schema и XSD не заявляется; требования к неизвестным полям и закрытости должны быть явно согласованы и отражены в документации профиля.

Таблица задаётся объектом с единственным массивом объектных строк. Массив становится непосредственно повторяющимся свойством этого объекта; вторая обёртка не создаётся. Прямой массив объектов без согласованного сценария адаптера отклоняется.

Простые списки допускаются только в представимых и документированных сценариях конвертации. Различие отсутствия и пустого массива, массив с верхней границей 1 и несовместимые табличные границы требуют отдельного решения; без него вход отклоняется. Required не усиливает minItems.

Вложенные группы учитывают имя ОбщиеСвойства. Самостоятельная строка является отдельным объектным типом, не таблицей. Порядок полей сохраняется: он может влиять на выбор варианта составного значения.

### Значения и ограничения

Обязательность скаляра задаёт minOccurs, а базовый профиль не выводит nillable=true из необязательности. UUID сохраняется как именованный UUID; Ref EnterpriseData не подставляется.

Существенные десятичные ограничения проверяются без округления через binary float. Enum соответствует базовому типу и фасетам. MultipleOf поддерживается только при точном представлении. Regex имеет явный совместимый профиль; неподдерживаемые конструкции отклоняются. Default проверяется как аннотация, не команда заполнения и не fixed.

### Результат и CLI

XSD компилируется через lxml.etree.XMLSchema до замены файла. Временный файл располагается в выходном каталоге; замена атомарна, прежний результат сохраняется при отказе. Совпадение входного и выходного пути отклоняется.

Ожидаемые ошибки содержат категорию, путь YAML и причину, выводятся в stderr с ненулевым кодом завершения. Файловые ошибки не выдаются за ошибки схемы. Глобальное подавление предупреждений удаляется. Интерфейс преобразования отделяется от CLI.

## Проверки и приёмка

Целевые тесты проверяют наблюдаемое поведение: минимальный файл без каналов; optional/required; UUID; простые и объектные ссылки; алиасы и циклы; коллизии; несколько сообщений и каналов; таблицу без второй обёртки; допустимые коллекции и явный отказ от непредставимых; enum; дубли; неверный required; неизвестные ключи; ссылки внутри examples; фасеты и точные десятичные значения; устойчивость результата; сохранение файла при ошибке.

XMLSchema проверяет положительные и отрицательные XML-экземпляры. Проверка XML не выдаётся за проверку JSON в 1С. Интеграционная гарантия требует отдельно согласованного запуска на платформе; без него результат обозначается как проверенный на уровне генератора и XSD.

Приёмка: все дефекты устранены точным преобразованием или явным отказом; нет молчаливой потери типов и ограничений; невалидный файл не выдаётся как успех; документация соответствует реализованному профилю; пользовательские изменения сохранены.

## Выполненные проверки ревью

Зависимости не устанавливались; воспроизводимая среда компонента должна быть настроена при реализации. Исходный скрипт и существующие XSD-примеры не изменены.

## Реализация

### Итоговое ревью required/min и выпуска XSD — утверждено и реализовано

Повторная проверка после принятия документации: устранено вычисление присутствия поля по округлённым XSD-фасетам ссылочного типа; теперь прямое описание и цепочка локальных ссылок используют исходную минимальную границу одной схемы. Например, integer с minimum=-0.5 не превращает нижнюю границу поля по ссылке в 0 из-за округления фасета до 0. Разделены структурная компиляция типов и регистрация default/examples: контекст допустимости null фиксируется после решения о nullable поля. Убрана повторная коррекция nullable в валидаторе, дублирование регистрации значений массивов, неиспользуемые признаки collection/is_table, дублирующая array_min и неиспользуемый импорт replace. Сохранены один файл реализации, порядок объявлений UUID/общие простые/простые полей/сложные типы, порядок properties, компактные аннотации с приоритетом title и исключение стандартных атрибутов XSD. Слои обратной совместимости и специальные случаи по именам примеров не добавлены.

Проверки повторного ревью: 63 теста прошли, включая дополненные проверки nullable default прямого массива и $ref, исходной числовой границы в прямом поле/$ref/алиасе, три воспроизводимых XSD-примера и AsyncAPI-4.15.1.yaml. compileall и diff --check для tools/xdto прошли. Изменения внутренней компиляции не потребовали изменения принятой продуктовой документации. Генерация XSD и проверка примеров подтверждены; фактическая сериализация JSON в 1С не проверялась и в область этой проверки не входит.

Пользователь поручил ревью всего скрипта и исправления, подтвердил независимость min и required и требование не записывать значения, совпадающие со стандартными значениями XSD. Это уточнение заменяет предыдущую ошибочную формулу minOccurs=0 для каждого поля вне required.

Исправления: lower больше не зависит от required; nullable определяется required независимо от lower. Nullable-ребро не делает рекурсивное содержание обязательным. Min по умолчанию равен 1 для всех типов. Эмиссия опускает minOccurs=1, maxOccurs=1, nillable=false и attributeFormDefault=unqualified, сохраняя отличающиеся значения. SchemaError хранит message для структурированного перевода категории; непредставимый XML-символ диагностируется по исходному пути значения. Проверка x-enumNames не принимает явно заданный null. Целочисленные десятичные границы массива принимаются как целые числа.

Валидация JSON/XDTO-примеров выделена из проверки XML-структуры: проверяются nullable, присутствие, вид значения, количество элементов и неизвестные поля; XMLSchema применяется к фасетам простых типов. Исходная JSON-форма не переводится в фиктивные XML-объекты для обхода различий null/количества. Nullable-список может быть null независимо от min/max; непустое значение сохраняет свои ограничения, null элементов не разрешается автоматически. Сама выходная XSD компилируется отдельно; различие XML и JSON/XDTO документировано.

60 тестов прошли, включая независимость required/min, стандартные атрибуты XSD, nullable-списки с диапазонами 2..3 и 0..0, общий min=1, рабочий YAML и воспроизводимость трёх примеров. Примеры XSD перегенерированы с прежними namespace/prefix/suffix; YAML сохранены без изменения. Проверка на платформе 1С не выполнялась. Коммит текущих исправлений не выполнялся.

### Поправка: поведение required/min/null — утверждена и реализована

Пользователь задал фактическое поведение 1С/XDTO и явно поручил обновить генератор и документацию. Для обязательного поля min=0 допускает пропуск незаполненного значения, ненулевой min сохраняет требование присутствия; для поля вне required разрешается null. ### Поправка: массивы среди реквизитов — утверждена и реализована

Итоговые проверки поправки: 44 теста прошли; compileall, git diff --check и проверка локальных Markdown-ссылок и закрытия кодовых блоков успешны. Коммит поправки не выполнялся.

Пользователь утвердил реализацию прямым поручением исправить скрипт и документацию. Интеграция с платформой 1С не запускалась.

Основание: пользователь подтвердил допустимость `TestDocumentPayload.tags`, `fixedTags` и `lines` из `tools/xdto/examples/legacy/asyncapi_example.yaml`. Ранее введённый запрет всех массивов среди нескольких свойств и всех простых списков чрезмерно ограничивает исходный контракт. Эта поправка заменяет соответствующие ограничения первоначального профиля после явного утверждения.

Область: `tools/xdto/generator/asyncapi2xsd.py`, тестовый файл рядом с ним, поддерживаемый пример и README; в `adapter/adapter/docs/project` — описание генерации и требования к YAML; в `tasks` — эта спецификация. Генератор остаётся одним файлом.

Простой массив среди реквизитов превращается в непосредственно повторяющийся элемент простого типа. Для `tags` границы — `0..unbounded`, ограничение длины применяется к каждому элементу. Для обязательного `fixedTags` — `1..3`, длина каждого элемента — `2..30`. Ссылки на простой тип сохраняют его вид, включая перечисления. Required не повышает minItems. Отсутствие и пустой список при нулевой нижней границе неразличимы на уровне повторяющихся XML-элементов; ограничения JSON-присутствия независимо от количества не должны молча имитироваться усилением нижней границы.

Массив объектных строк среди реквизитов превращается в одиночное свойство объектного типа таблицы. Этот тип содержит единственное повторяющееся свойство `row` с типом строки. Required определяет minOccurs свойства таблицы; minItems/maxItems определяют границы row. Для обязательного `lines` с minItems=1/maxItems=100: свойство lines обязательно, строка имеет границы `1..100`. Типы таблицы и строки именуются отдельно и проверяются на коллизии. Имена row и типов являются моделью XDTO и не добавляются в контракт JSON как дополнительные бизнес-поля.

Уже явный контейнер с единственным массивом объектных строк сохраняет прямое повторяющееся свойство, без второй обёртки. Нельзя определять контейнер только по количеству properties так, чтобы объект сообщения с одним массивом неожиданно менял значение без документированного правила; действующее соглашение явного контейнера сохраняется и описывается отдельно от автоматической обёртки табличного реквизита.

Проверки: независимые минимальные схемы трёх вариантов, совместная схема с обычными реквизитами, простой массив по ссылке/enum, XML-экземпляры с нарушением длины и количества, обязательность таблицы независимо от количества строк, отсутствие второй обёртки у явного контейнера, коллизии имён нескольких таблиц. Проверяются default/examples исходной JSON-формы через соответствующее представление XML. Генерация XSD не объявляется интеграционной проверкой конвертации в 1С. Остальные неподдерживаемые конструкции старого примера оцениваются отдельно; весь legacy-файл не становится эталоном автоматически.
